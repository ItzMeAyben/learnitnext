<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser localStorage ↔ app state | The `learnit_onboarded` flag is client-controlled storage read by the gate |
| No network trust boundary | This plan adds no API surface; onboarding is purely client state |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Tampering | OnboardingGate localStorage flag | accept | User can forge/clear the flag to skip onboarding — it is UX routing, not a security control; no protected resource exists behind it (single-user personal tool, REQUIREMENTS.md "Auth / multi-user: out of scope") |
| T-01-02 | Spoofing | onboarding wizard | accept | No auth anywhere in the app by design; nothing to spoof |
| T-01-03 | Repudiation | onboarding flag | accept | No audit trail needed for a local first-run flag; no sensitive action occurs |
| T-01-04 | Information disclosure | OnboardingGate | accept | Flag stores the literal '1'; zero PII/secrets |
| T-01-05 | DoS | wizard useState | accept | Pure client state; a reload resets it; no server resource involved |
| T-01-06 | Elevation of privilege | onboarding page | accept | No privileged operations exist in the mock |
</threat_model>
