Verified bug report (01-RESEARCH.md, Pitfall 1 — reproduced on the dev server
2026-08-14): `GET /api/subjects/Distribution` returns AI Agents JSON and
`/pathway/Distribution/print` renders an AI Agents h1, because `params` is a
Promise in Next 16 so `params.subjectId` is `undefined`, and the store fallback
maps `"undefined"` to SUBJECTS[0]. Both unknown-ID URLs currently return HTTP 200.

Next 16 rules that govern this plan (01-RESEARCH.md, doc-cited):
- `params` is a Promise — server code must `const { subjectId } = await params`.
- `notFound()` from `next/navigation` throws to the nearest `not-found.js` boundary
  and works in route handlers and server components.
- A root `app/not-found.js` covers every `notFound()` throw with no nearer boundary
  AND all unmatched URLs.
- `decodeURIComponent` throws URIError on malformed input like `%` — wrap it
  (unknown/invalid ids must 404, never 500).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| HTTP client → route handler `/api/subjects/[subjectId]` | Fully client-controlled path segment reaches server code |
| URL path segment → store lookup | Raw (encoded) id is decoded then matched against in-memory SUBJECTS |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Tampering | decodeURIComponent(subjectId) | mitigate | try/catch around decode → 404 on URIError, so `/api/subjects/%` and `/pathway/%/print` return 404 instead of an unhandled 500; lookup is exact-match `find` against a fixed array — no injection surface |
| T-02-02 | Information disclosure | getSubjectById fallback | mitigate | Removing `?? SUBJECTS[0]` (this plan) stops the API from confidently returning WRONG data (AI Agents) for probed ids — unknown ids now get a bare 404 with no store contents |
| T-02-03 | Spoofing | /api/subjects routes | accept | No auth in a single-user in-memory mock; no PII served (REQUIREMENTS.md: auth out of scope) |
| T-02-04 | Repudiation | API/print | accept | Read-only GET surface; no audit trail required |
| T-02-05 | DoS | route handler | accept | Lookup is an O(n) find over a 3-element in-memory array per request; no unbounded work introduced |
| T-02-06 | Elevation of privilege | store.js | accept | GET-only handlers; this plan removes behavior rather than adding mutations |
</threat_model>
