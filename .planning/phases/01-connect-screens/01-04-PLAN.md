<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| URL query string (?subject=) → rendered text + href construction | Fully client-controlled string is displayed and interpolated into Links |
| No new network trust boundary | No new fetches; quiz still imports static QUIZ_ITEMS; listen/session read existing APIs only |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Tampering | `?subject=` rendered + interpolated into hrefs | mitigate | Every href built with `encodeURIComponent(subject)` (specified per control); React escapes the rendered text nodes; the param never reaches a fetch URL or store lookup this phase — display/links only |
| T-04-02 | Tampering | query param consumed without Suspense | mitigate (availability) | `<Suspense>` wrapper is an explicit acceptance criterion enforced by `npm run build` — prevents a build-time break, not a security issue per se |
| T-04-03 | Spoofing | quiz/listen defaults | accept | Mock content; no user identity involved |
| T-04-04 | Repudiation | navigation wiring | accept | No state-changing actions introduced (Save a link / actions explicitly untouched) |
| T-04-05 | Information disclosure | subject context display | accept | Param is echoed back to the same client that supplied it; no server data keyed on it this phase |
| T-04-06 | DoS | client pages | accept | Pure client rendering; no unbounded input handling |
| T-04-07 | Elevation of privilege | session links | accept | All destinations are ordinary app screens |
</threat_model>
