# Phase 2 — UI Design Contract

> Visual and interaction contract for Phase 2 (UI Design & Responsive Overhaul).
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Governing principle (D-06):** this contract SYSTEMATIZES the app's existing
> visual language — dark-ink surfaces, lavender-gray canvas, white cards, purple
> accent, lime brand moments, rounded pills, flat elevation — into tokens. It
> does not invent a new brand. Odd one-off values in the current screens are
> absorbed into the nearest token; only values that fail WCAG AA contrast are
> deliberately refined (each refinement is marked and justified in §7.6).

## 2. Token Architecture (how tokens reach the screen)

Two halves, both required:

1. **`app/globals.css`** grows from the 3-line reset to: the reset, `:root`
   custom properties (every color/type/spacing/radius token in §4–§7), the
   interaction-state layer (§10: `:focus-visible` ring, `.btn-*` /
   `.tab-*` / `.skeleton` classes, `@keyframes shimmer`, the
   `prefers-reduced-motion` block, `.only-phone` / `.only-tablet` /
   `.only-desktop` visibility helpers, `@media print` rules). Still one small
   file (~150 lines); no framework.
2. **`lib/tokens.js`** exports the same values as JS constants plus helpers:
   - `tokens` — flat map mirroring the CSS vars (`tokens.color.ink`,
     `tokens.space.md`, `tokens.type.body`, …)
   - `pill(variant)`, `card()`, `statusPill(status)` — style-object factories
     for the §9 vocabulary
   - `GLYPHS` — the standard text-glyph map
   - `useMediaQuery()` / `useViewport()` — suspense-safe hook returning
     `'phone' | 'tablet' | 'desktop'` for JS-dependent structural branches

**Rule for executors:** static styling stays in inline `style` props built from
`tokens`; anything with `:hover` / `:focus-visible` / `:active` / media-visibility
needs the CSS class layer (inline styles cannot express pseudo-classes).
Interactive elements therefore take a className (`.btn`, `.btn-primary`, …) for
their state styles and inline tokens for layout. Container-driven responsiveness
(CSS grid `auto-fit`/`minmax`) is preferred over JS breakpoints; JS branching is
reserved for structural swaps (table→cards, bottom bar, pane stacking).

## 6. Typography

Two weights for the whole app. Workhorse weight is 500 (Plus Jakarta Sans at
500 reads like other sans' 400 — this preserves current rendering); emphasis is
700. Current 600 → 700; current 800 → 700 (display keeps its size, loses the
extra weight step).

| Role | Size | Weight | Line Height | Letter spacing | Usage |
|------|------|--------|-------------|----------------|-------|
| Caption | 12px | 500/600→700 | 1.4 | +0.6px when uppercase | Status pills (700), eyebrows (700 uppercase), meta lines, table headers, timestamps, nav labels on bottom bar |
| Body | 14px | 500 | 1.55 | 0 | Body copy, buttons, nav tabs, table cells, list rows, quiz options (16→Body bold reads fine at 14/700? No — see exception) |
| Heading | 20px | 700 | 1.3 | −0.3px | Card and section headers, stage titles, material card titles |
| Display | 32px | 700 | 1.15 | −1px | Page h1s (Library, Pipeline, Today greeting), hero titles, quiz question, large stat numerals (line-height 1) |

Absorption map (existing → token): 10.5, 11, 11.5, 12, 12.5 → **Caption 12** ·
13, 13.5, 14, 14.5, 15, 16 → **Body 14** · 17, 18, 19, 20 → **Heading 20** ·
26, 28, 30, 32, 36, 40, 44 → **Display 32**.

Exceptions (2, both deliberate):
- **Quiz question:** Display 32 is too shouty for a 2-line question on phone;
  quiz question uses **Heading 20 / 700 / lh 1.35** (down from 30 — improves
  phone fit, keeps hierarchy via the card).
- **Stat numerals on lime/subject-color hero cards:** Display 32 at lh 1
  (absorbs 26/34/46 numerals; the streak "37" becomes 32 — calmer, on-system).

Mono (JetBrains Mono) at Caption 12: playlist IDs, bot token fields, run log,
`added` dates in Library if executor prefers tabular. Uppercase eyebrows:
Caption 12 / 700 / +0.6px tracking (absorbs `STEP 1 OF 5`, `NOW PLAYING`,
`READING PATH`, `NOTEBOOK · N SOURCES`).

## 10. Interaction States

Mechanism: CSS class layer in `globals.css` (inline styles can't do
pseudo-classes). Prescribed rules:

| State | Rule |
|-------|------|
| Hover | Buttons/nav/links only (§9.1, 9.4): bg shift one surface-step; links underline. Nothing moves or grows on hover. |
| Active | `transform: scale(.98)` on buttons/tabs, 100ms. |
| Focus-visible | `outline: 2px solid var(--color-accent); outline-offset: 2px;` on every focusable element, globally via `:where(a, button, input, select, [tabindex]):focus-visible`. On dark surfaces (Listen dark, Session, ink cards) a `.on-dark` class swaps the ring to lime. Never remove the ring (`outline: none` banned). |
| Disabled | `opacity: .55; cursor: default;` (matches existing onboarding Back at step 1) — EXCEPT the not-yet-wired action pills (§9.1) which stay full-opacity `disabled`. |
| Touch targets | Every interactive element ≥ 44×44: buttons/nav/bottom-bar items/filters/breadcrumb links/quiz options (already ~57px). Pathway reorder arrows: on phone the two arrows render as a full-width row of two Ghost pills ("Move up" / "Move down"), each 44px. |
| Reduced motion | `@media (prefers-reduced-motion: reduce)`: kill shimmer, transitions, and `scrollIntoView` smoothness (JS checks `matchMedia` and uses `behavior:'auto'`). Nothing else animates in this app — no entrance animations, no page transitions (discretion call: micro-motion stays at hover/skeleton level only). |
| Zoom/text | Layouts survive 200% browser zoom and 320px content width (WCAG 1.4.10): no fixed-width text containers except mono token fields (which scroll internally). |

## 11. Accessibility Table Stakes (D-07)

1. **Contrast:** §7.6 targets; checker samples pills, meta text, links.
2. **Focus:** visible ring everywhere (§10); DOM order = visual order; phone
   bottom bar sits LAST in DOM (after `main`) so tab order reads
   content→nav; a "Skip to content" link is the first tab stop (hidden until
   focused).
3. **Semantics:** Phase 1's span→Link/button work stays (D-11). Every screen
   has exactly one `<h1>` (Display). Landmarks: `<header>` (TopNav), `<nav
   aria-label>` ×2 (top + bottom bar; hide the inactive one with `display:none`
   per breakpoint, not just visually), `<main>` wrapping page content. Lists of
   subjects/sections/sources are `<ul>` or `role="list"`. Library grid keeps
   table semantics (`role="table"` + `aria-sort` on headers, sr-only caption
   "Your saved links"). Status pills on failed rows pair with sr-only text
   "status: failed". Waveforms are decorative (`aria-hidden`); player buttons
   get `aria-label` ("Play", "Skip back 15 seconds").
4. **Forms (onboarding step 3):** token input is a real `<input>` with a
   `<label>` ("BotFather token") and monospace styling; "Verify" is a
   `<button>`.
5. **Zoom/targets:** §10 rows 6–7.
