OWNERSHIP RULE (applies to every element you give a class): any property touched by a :hover/:focus-visible/:active/[aria-current] rule (background, color, opacity, transform, outline) must NOT be set inline on that element — inline = layout (padding/grid/gap/width), class = state.

Route rules (bundled docs, verified in 02-RESEARCH):
- `app/page.js` and `app/(dashboard)/page.js` CANNOT coexist — two files resolving to `/` is a build error. Move, don't add.
- `cookies()` is async: `const cookieStore = await cookies()`. Reads are legal in Server Components and opt the route into dynamic rendering. SETTING cookies during Server Component render is illegal — writes belong in a Server Action (`'use server'` file).
- A Server Component page may render Client Components (`<Landing/>`, `<Today/>`); the reverse import direction is what's forbidden.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → Server Action app/actions.js | `completeOnboarding` is reachable via direct POST (documented Next behavior for Server Functions) |
| cookie learnit_onboarded → server render branch | fully client-controlled value decides landing vs dashboard at `/` |
| localStorage (Phase 1 legacy) → document.cookie | migration shim copies a client-readable flag into a client-writable cookie |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-02-01 | Elevation/Tampering | app/actions.js completeOnboarding | accept | Action sets ONE non-sensitive preference cookie for the caller themselves; worst case a visitor "completes onboarding" for their own browser. No auth, no data mutation. If actions ever touch data, add auth checks then. |
| T-02-02-02 | Tampering | learnit_onboarded cookie value | accept | Cookie only gates landing-vs-dashboard RENDER choice; no security decision derives from it (all routes stay public by design — single-user tool) |
| T-02-02-03 | Spoofing/Tampering | migration shim | accept | Copies the user's OWN localStorage flag to their OWN cookie; non-httpOnly is deliberate so the shim can write it; maxAge 1y; no PII |
| T-02-02-04 | Tampering (XSS) | components/Landing.js | mitigate | All copy is static JSX (React auto-escapes); subject data renders via JSX text only; NEVER introduce dangerouslySetInnerHTML; keep copy as literals so this stays true (`grep -rn dangerouslySetInnerHTML app components` must stay empty) |
| T-02-02-05 | Information disclosure | app/page.js cookie read | accept | Cookie presence (boolean) is the only thing read; value content is never echoed into HTML |
</threat_model>
